# Aufbau eines Pflichtenhefts (analog zu IEEE/ANSI 830-1998)

| Kapitel | Beschreibung |
| --- | --- |
| Deckblatt, Verzeichnisse | Deckblatt: Titel, Datum, Version, Autoren und Kundename.<br>Wichtige Verzeichnisse: Inhalts-, Abbildungs-, Tabellen-, Abkürzungs- und Anhangverzeichnis. |
| Vorwort | Sollte die erwartete Leserschaft des Dokumentes festlegen und eine Versionsgeschichte beschreiben, die eine Begründung für die Entwicklung einer neuen Version und eine Zusammenfassung über die Veränderungen bei jeder Version des Dokuments beinhalten sollte. |
| Einleitung | Sollte die Notwendigkeit des Systems beschreiben, kurz seine Funktionen darlegen und erklären, wie es mit anderen Systemen zusammenarbeiten wird, sowie erläutern, wie das System mit den Unternehmenszielen übereinstimmt bzw. diese unterstützt. |
| Begriffe | Sollte die im Dokument verwendeten technischen Fachbegriff festlegen. Dabei dürfen keine Erfahrung oder Fachwissen beim Leser vorausgesetzt werden. |
| Definition der Benutzeranforderungen | Die für den Benutzer bereitgestellten Dienste und die nicht-funktionalen Anforderungen werden hier beschrieben. Diese Beschreibung kann in natürlicher Sprache, Diagrammen oder anderen für die Kunden verständlichen Notationen erfolgen. Produkt- und Entwicklungsstandards, die befolgt werden müssen, sollten ebenfalls hier festgelegt werden. Die Anforderungen sind mit einer ID zu versehen. |
| Systemarchitektur | Sollte einen groben Überblick über die erwartete Systemarchitektur geben, der die Verteilung der Funktionen auf Systemmodule/-pakete zeigt. |
| Spezifikation der Systemanforderungen | Sollte die funktionalen und nicht-funktionalen Anforderungen detailliert beschreiben. Die Beschreibungen sind mit einer ID zu versehen. |
| Systemmodelle | Sollte eines oder mehrere Systemmodelle festlegen, die die Beziehungen zwischen den Systemkomponenten und dem System und seiner Umgebung aufzeigen. Dies können Klassen-, Datenfluss- und semantische Datenmodelle (ERM) sein. |
| Systementwicklung | Sollte die grundlegenden Voraussetzungen, auf denen das System basiert, und erwartete Veränderungen aufgrund der Hardwareentwicklung, Veränderungen der Benutzeranforderungen etc. beschreiben. |
| Anhänge | Die Anhänge sollte genauere spezifische Informationen beinhalten, die sich auf das zu entwickelnde System beziehen. Beispiele sind: Hardware- und Datenbankbeschreibungen. HW-Anforderungen legen die minimale und optimale Konfiguration des Systems fest. DB-Anforderungen definieren die logische Verwaltung der vom System verwendeten Daten und die Beziehungen zwischen diesen Daten. |
| Index | Das Pflichtenheft kann mehrere Indizes enthalten. |
